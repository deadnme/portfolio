Twitch Emote No-Restart

Greasy Fork (opens in a new tab) Source on GitHub (opens in a new tab)

Personal project, published. Version 2.6.1, 697 lines of vanilla JavaScript, zero dependencies, GPL-3.0.

A browser userscript that stops animated Twitch, 7TV, BTTV and FrankerFaceZ emotes from restarting every time Twitch’s chat re-renders. It decodes each emote once through the WebCodecs ImageDecoder, gives every copy of an emote one shared clock, and paints them from a worker onto an OffscreenCanvas so Twitch’s own main-thread work cannot stall the animation.

Most of the effort went into profiling. A test harness running at 20 messages per second showed the first version forcing thousands of synchronous layout reads per second; I fixed that by splitting each frame into a strict read phase and write phase and capping occlusion sampling to a 3 ms budget. Every failure path falls back to the native image rather than leaving a hole.

For v2.6.1 I rewrote it from 1,927 lines down to 697 without changing its behaviour, checked against the same test suite. I then built a stress test that floods chat with real 7TV, BTTV and FrankerFaceZ emotes at up to 60 messages per second. It caught a bug the earlier release had shipped with: under heavy load, about one in four emotes briefly showed the wrong image. That is now zero.

Profiling drove the v2.4.2 and v2.5.0 releases: roughly 7,900 forced hit-tests per second eliminated, and 6,700 style recalculations per second cut to a few hundred. The v2.6.1 rewrite took the code from 1,927 to 697 lines, and wrong-emote canvases under a 60-messages-per-second flood went from 23% to 0%.

Git publish automation

Source on GitHub (opens in a new tab)

Personal project. Bash and Git.

A Bash script behind a single publish alias that stages, commits and pushes changes to a GitHub repository. It refuses to run from a detached HEAD, the wrong branch, or in the middle of a merge or rebase. When a push is rejected it rebases and retries once and never force-pushes. A dry-run mode shows what it would do, and a watch mode publishes on its own once edits have sat still.
